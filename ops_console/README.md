# Ozon 多店铺运营工作台

独立的本机运营界面：退款/售后记录、库存预警、买家会话、浏览器通知及人工回复。
它不导入 FlowHub 发布模块，不打开 FlowHub 数据库，不修改商品库存、不批准退款。

## 运行

Python 3.12+，依赖 `fastapi`、`uvicorn`，另需系统 `/usr/bin/curl`。

```sh
python -m ops_console --data /absolute/private/data --port 8768
```

打开 `http://127.0.0.1:8768`。服务仅监听本机回环地址，使用 HttpOnly SameSite cookie、
CSRF token、Host/Origin 校验和 CSP；不是公网或多人登录系统。不要直接暴露端口到公网。

独立数据目录中的 `stores.json` 为 JSON 数组，每条包含 `id`、`name`、`client_id`、`api_key`。
`id` 使用飞书记录ID；数据目录权限700、凭据文件600，不提交密钥。密钥仅通过子进程stdin
传给官方 Seller API 的 TLS 验证请求，不出现在浏览器、命令参数或日志里。

演示模式使用完全离线的模拟接口（页面有明显标识）：

```sh
python -m ops_console --demo --data /tmp/ozon-ops-demo --port 8876
python -m pytest -q tests/ops_console
```

## 数据与行为

- 27家等任意数量店铺由当前导入的配置决定；新增/改密钥后需受控更新配置并重启。
- 买家列表每60秒、售后每10分钟、库存每15分钟读取；平台限流/错误后退避。
  全局最多3个API请求并发，首次同步及大店铺实际间隔可能延长。
- 读取采用完整分页，重复游标/页数上限视为失败，保留上次快照；失败和过期时间在界面显示。
- 售后合并FBO/FBS与rFBS，保留平台状态。不将售后申请数、投诉率或商品金额当作退货率/退款额。
  平台未提供或未识别的状态需人工核对。
- 库存是平台`present`合计，预留量单列；默认0或严格低于5件预警。
  空stocks为未知，归档商品从预警排除。不能由平台库存推断供应商实物库存。
  忽略提醒、阈值更改只写本机运营数据，不操作平台库存或既有人工下架决策。
- 仅`BUYER_SELLER`进入买家通知，水位和事件持久化；系统通知不计入买家未读。
  浏览器需用户授予通知权限并保持标签页打开；不提供关闭浏览器后的Web Push。
  电脑休眠/离线无法实时检查，恢复后继续。消息读取不调用标记已读接口。
- 回复仅由用户点击「发送回复」或快捷键发起，原文发送。俄语快捷短语只填草稿。
  写请求只执行一次；先保存发件日志，再调用平台。超时/无法确认的响应进入待核实状态，
  阻止该会话继续发送，用户核对平台后可在界面明确确认结果。不会自动重试。
  进程中断会把未完成发送持久化为待核实；同一request_id不会重复发送。
- 自带本机草稿、库存CSV导出（防公式注入）、售后详情、跨店筛选、分页和同步错误说明。

## 部署范围

从`codex/store-operations-console-20260919`隔离工作树交付独立`ops_console`目录；
正式运行快照和运营数据放在`~/Library/Application Support/Ozon Operations/`。
使用单独的`com.ozon.operations` LaunchAgent；只启动此模块，不启动任何发布器。
唯一生产发布目录仍是主FlowHub。部署记录在工作区deliverables目录。
更新/回退只切换运营程序快照，保留stores.json、operations.sqlite3及发送日志。

## 界面设计

视觉：浅灰工作区、白色表格与低饱和绿色操作，优先呈现可扫描的店铺状态。
内容：总览负责定位问题；售后表负责查看申请；库存表负责核对与提醒设置；消息页负责回复。
交互：侧边栏店铺切换、会话选择、轻量状态反馈；尊重减少动态效果设置。
