# 分阶段补资料机制（2026-09-18）

启用配置为 data/repair-workflow.json。估价资料和上架资料各有一个独立工作通道，不再因上架积压把估价准入上限压到 8，也不再以最近任务耗时决定第二个通道能否运行。估价积压默认上限 16；主流程总并发、审核与利润要求仍生效。

每个 SKU 分 facts（基础事实）、source（原采集账本获取资料）、validate（正式上架字段校验）三个阶段。每完成一段即保存商品事实与 repair_workflows 检查点。默认阶段超时分别为 60/120/120 秒；重启从未完成阶段继续。repair_workflow_events 记录每段耗时、原因和缺失字段。原 SKU 租约仍是唯一所有权依据。

网络、容量、远端处理中按 30～900 秒退避，不因历史重试次数自动隔离；确定缺失字段转为明确人工补充，避免无限循环。连续 30 分钟无阶段进展触发监控告警。人工暂停仍有效。

原 SourceCollector 的未知写入只回查规则、原上架与删除账本、同款和利润审核均保留。该模块不导入商品或设置库存。实际完成仍按首次 stock_verified 统计。

回退：先暂停并排空主流程，在 repair-workflow.json 设置 enabled=false 后重启主工作进程，再恢复原暂停状态；必要时回退本次代码提交。保留所有 repair_workflows、事件和原业务账本，不回滚数据库。已转人工的数据应逐条补充真实字段后重入，不批量伪造资料或恢复历史隔离项。
