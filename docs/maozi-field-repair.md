# 毛子 ERP 补资料与发布定价修复

## 修正的根因

2026-09-12 的 72 个待补资料商品实际上已拥有完整包装、属性、采购报价和近期批准的利润测算。旧代码把参考竞品价格的 6 小时有效期直接施加于已批准的目标上架价，造成误拦截。这里修正的是定价意图与市场观察的混用，不是伪造新价格或放宽利润门槛。

`approved_price_intent` 仅接受近期 matched 审核：compareBot 已批准，供应商 ID 与采购成本绑定，目标售价与利润输入逐值一致。保留原参考价、原采集时间和原批准时间。上架仍使用原已批准售价；不宣称它是当前市场价格。审核本身过期或成本、供应商绑定不一致仍需重算。

## 毛子资料模块

`pipeline_modules/repair.py` 按字段检查标题、图片、链接、重量、三边尺寸、属性和可用估值输入。

- 参考价过期但存在有效批准售价：使用原定价意图，不重复拉取市场报价。
- 真正缺少可用价格：调用毛子 `/api.chrome/sku3`，SKU 同时放查询参数和 POST body；必须同 SKU、同卖家且 `update_sales=false` 才接受价格。
- 包装或属性缺失：复用 SourceCollector 的收藏→采集草稿→详情流程。收藏和草稿采用已有状态记录，不盲目重复创建。详情包含 common_attributes、重量及包装三边。
- 保存每次补采前后缺项、来源、时间和接口状态到 plugin_repair_events；空值仍为空值。
- 补资料与发布截止分离。发布过期不阻断只读缓存补采；新发布须具有新的授权路由及截止时间。旧一小时窗口不延长。
- 补齐后返回审核队列，不能直接绕过采购和利润检查。尚未提交的原计划只有在售价、成本、供应商和包装不变时才能更新审核证据。

毛子官方插件源码也表明：sku3 返回缓存和 update_sales/update_variant 标记，插件另行取数后回填。因此 update_sales=true 不代表 ERP 正在替本地脚本主动更新。官方源代码下载链接来自 [毛子官网](https://www.maozierp.com/)，本次仅下载阅读，未安装或启动 Chrome。

## 调度与速度

沿用独立补采、审核、提交和回查通道。库存回查和已提交任务优先，ready 任务优先于未准备任务。同 SKU 和同店铺互斥，保留全局毛子 API 限速。

同一次推进中缓存相同只读检查 30 秒，任何写入前清空本次缓存，库存和在线商品回查永不缓存。已明确授权的未知配送模式不再额外发请求反复确认“未知”；证据中明确 FBO 或禁止跟卖仍拦截。

### 补采失败与价格引导

尚未批准测算的候选也可先补包装和属性：以真实 CNY 价格创建采集收藏；RUB 报价按毛子 RUBCNY 接口转换。没有真实价格时只查已有收藏，不写入零元占位收藏。价格接口失败不阻断独立包装补采，已经取得的资料和失败类型一并落库，下轮只补缺项。

2026-09-12 17:55:58 运行快照：恢复的 72 件中，15 件已验证 selling 且目标仓 present=99，15 个新 SKU 无重复，1 件平台导入失败，56 件仍在队列。累计约 24.85 分钟，尚未完成整小时验收，不能宣称达到 40 件/小时。实时明细由 `reports/repair-maozi-20260912/status.py` 生成。

共享限速下的只读单次传输对比：Node 11.97 秒，HTTPX 14.86 秒，均成功。此样本不能证明切换传输可提速，未启用 HTTPX 替换默认发布传输。实验源码保存在 reports 目录，不进入生产调用链。

## 晚间续跑补充

“继续处理”后对完整但过期的资料也触发真实毛子详情补采。已有平台 offer 在价格、包装一致时可刷新审核后继续库存，无需重新创建商品。重新测算改变供应商或成本时，先通过既有批准条件并校验外部售价、包装、offer 不变，再以显式 plan_revisions 保留新旧采购计划；不静默覆盖旧证据。详见 `reports/continue-maozi-20260912-2209/README.md`。
