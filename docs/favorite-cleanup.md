# 毛子收藏容量自动清理与来源留存

配置：`data/favorite-cleanup.json`。后台随 FlowHub worker 启动，seed 暂停时也暂停。

默认每 60 秒检查一次，收藏占用达到 95% 才触发，每批最多 1000 条，目标占用降至约 2/3（容量 3000 时保留约 2000 条）。实际只删除符合条件的数量，不为凑满批次扩大范围。仅处理 FlowHub 已确认 selling 至少一小时、毛子标记已导入的唯一源 SKU 收藏；删除前按原店铺与线上货号实时确认仍在售且库存大于 0。

必须有完整源 SKU、seller_id、source_relation.root_seeds 和对应发布日志。缺失关系、重复收藏、未上架、在途租约、暂停、数据库/归档文件保存失败都不会删除。

## 保留哪些数据

删除前在 `favorite_cleanup_receipts` 中加密保存收藏完整记录、源商品、来源证据、根种子及其本地记录、发布日志、线上回查结果。独立副本位于 `data/favorite-lineage-archive/<sha256>.json`，权限 600，写入和 fsync 完成后校验 SHA256，才提交删除请求。

不删除或改写 sourcing_products、sourcing_seeds、sourcing_evidence、卖家扩展关系、采集游标和发布记录。因此源商品、卖家及根种子仍可从本地库追溯；毛子收藏 UI 中该收藏消失是预期行为。本地数据库、归档目录和 master.key 应一起备份；自动清理不提供异地备份。

只调用 `/api.product.favorite/toggle` 的 `status=false` 删除收藏。不归档线上商品、不更改库存、不删除草稿。删除后的完整分页回查确认原收藏 ID 消失，才标记 deleted。超时或结果未知保留 intent/unconfirmed，不盲目重复删除；后续周期仅回查。

此清理解决收藏容量问题，不代表发布资料和其他审核条件自动通过。现有的历史“容量拒绝误记为结果未知”需要依据原始明确拒绝证据恢复，不能据容量释放直接重放所有未知请求。

## 2026-09-28 按依赖回收模式

显式配置 `mode: reclaim_unused`、`include_unrecorded: true`、授权说明及
`target_ratio: 0` 后，原 worker 的收藏清理任务按远端收藏清单工作。到高水位
启动一个持久批次，分段清完该批可回收收藏，低于触发水位也继续；仅保留有
活跃队列、未确认发布/采集、租约或删除回执的记录。用户授权的无记录收藏
同样归档回收。此模式不要求线上库存大于零，也不要求额外创建独立草稿。

发布、采集及清理共用 SKU 互斥；删除前保存本地资料和完整远端收藏，持久化
意图后仅发送一次取消收藏。未知结果只读回查；不会修改线上商品、库存、
人工决定、源商品或已存在的 8 条草稿保护证书。清理失败保存游标和错误，
下周期继续。`verification_delete_limit` 可限制真实验证阶段的累计删除数，
移除后续跑原批次。

新增收藏的明确满额拒绝记为 `waiting_favorite_capacity` 依赖等待，不增加
失败次数、不进入未知写入超时隔离；容量恢复后沿用原发布身份及原审核规则。
历史隔离任务只允许按明确拒绝凭证、原身份及远端无导入证据单独恢复。
