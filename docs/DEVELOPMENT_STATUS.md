## 验证口径

本轮 Python 测试 232 项通过；原生采集及独立脚本 Node 测试 15 项通过。全仓 Ruff 仍有历史及测试 fixture 导入问题，未将 lint 宣称为全绿。独立采集比较的旧成绩为约十分钟 25 页、197 个 SKU；归一化去重吞吐约提升 4.09 倍。不同时间和起始页不是严格控制实验。

采集商品只是待核查候选，不等于通过销量、重量、利润、物流与下架清单检查，不直接触发上架。全店结果包含开发中故障修复和断点续跑，不是十分钟完成全店。原始 HTML、商品清单和运行数据库仅在私有工作区保存。

## 运行依赖与协作重点

Python 3.12+；Node 桥接按对应文档配置。部分真实模块需要相邻的 `FlowEF-production`、`flow_b_ef`、`maozi_direct_new_method`、`ozon-runtime` 等工作区依赖，它们不包含在此仓库中。克隆本仓库可开发核心及运行测试，不能据此认定真实发布链路已配置。

优先工作：

1. 将本机兼容依赖替换为明确配置的接口/插件，并补充干净环境安装验证。
2. 核查真正的 ERP 整店分页接口，解决浏览器依赖；榜单筛选不能冒充整店覆盖。
3. 多店小批验收与长时间运行，记录失败率、恢复时间和去重产出。
4. 明确分开本地 FlowHub 队列与外部正式发布流程，避免把来源候选、提交成功和库存可售混为一谈。
5. 完成远程 HTTPS 部署、备份恢复和单执行器切换验收。

商品实时数量变化很快，公开仓库只记录能力及验证口径；实际账号、额度与待处理商品以私有审计为准。
