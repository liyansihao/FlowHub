# 网站商品上下架控制

用户追加规则：同款上架、不同款下架；每件商品始终保留网站上的上下架操作入口。

网站快照现在保留本租户全部 plugin_pipeline 商品，按页显示。审核后的记录不再隐藏。每件商品显示目标店铺，并有独立上架、下架按钮。同款确认产生上架指令；不同款确认产生下架指令。操作有版本校验和 human_reviews 审计。

`product_listing_controls` 保存每件商品的最新意图、阶段和原始请求。`listing_controls.run` 随现有 FlowHub worker 启动。上架复用原发布台账、SKU 全局锁、店铺仓库配置及毛子导入接口；已有原商品优先回查或恢复，不重新创建。下架只定位本店精确货号，清零全部已知可售仓库并回查后归档，最后回查归档状态。未找到本店发布记录标为 no_listing，不冒称已完成一次下架，也不操作来源卖家。

网站上架意图以当前用户选定的可用普通售价或最低跟卖价为售价决策，保留原报价时间。该意图不以利润门槛或本地缺少属性副本拒绝已确认同款；毛子按来源 SKU 导入，平台仍负责验证真实商品属性。实际重量与尺寸、店铺容量、明确下架清单、品牌型号冲突和已知跟卖限制继续验证。没有假造属性或利润。

正在排队或等待回查的上架，可在没有活跃 SKU 操作锁时用下架指令撤销。下架结果未知期间不会交叉发送恢复请求。恢复上架前再次读取飞书明确下架清单。所有网络写入的不确定结果保留原记录并回查，库存写入使用指定绝对值；后台不把接口成功当作可售成功。

首次派发清单与实时结果保存在 reports/review-listing-control-20260915/。198件同款请求上架，2件不同款请求下架。长时间的导入/库存回查由持久 worker 继续处理，页面展示 queued/running/waiting/listed/unlisted/no_listing/blocked 阶段及具体原因。临时加速脚本可关闭，正式 worker 独立恢复处理。
