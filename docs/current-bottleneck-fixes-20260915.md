# 当前根因修复

## 改动范围

1. 待补资料饥饿与超时遗漏：有补资料积压时入队预留1个处理名额（保持总并发上限）；在补资料通道优先处理已完成审核且首次等待发布资料的任务，同时保留首次测算与重试的原有顺序。进入needs_fields记录repair_wait_started_at；无失败次数的排队超过30分钟也转入待处理，兼容历史updated_at/requested_at。活跃租约不清理，保留恢复凭据。
2. 店铺额度：实时额度检查结果持久化；被判无额度的店铺不接收新候选。独立循环每分钟最多复查一家到期店铺，同一家间隔15分钟，查询失败保持停接状态。原发布及库存守卫不变，已绑定任务不搬店、不重发。
3. 历史回查：manual_review且仍等待回查的任务走独立单通道，正常reconcile排除这些任务。收藏尝试耗尽后每小时回查，其他历史等待至少15分钟，仍保持原journal、原offer和未知写入保护。恢复为正常发布阶段后自动回到正常通道。
