# 先读详情、按缺项补草稿

由 data/direct-first.json 的 enabled 启用。补资料顺序：复用有效字段；按需读取已有 Seller API 身份信息及毛子 /api.chrome/sku3；仍缺必要资料时读取公开 Ozon 商品详情；最后仅用毛子草稿填补缺失或过期的字段。资料齐全时不再触发外部补资料请求。

详情页仅接受 JSON-LD 中唯一且 SKU 精确匹配的 Product。重量只接受明确标注包装重量的字段，尺寸只接受包装尺寸和明确的毫米／厘米单位，商品本体尺寸不当作包装尺寸。详情页文字属性保留在 public_characteristics，不伪造上架属性 ID。毛子 sku3 当前真实响应只有 SKU/variantId 和更新标记时，不把这些当作完整资料，也不把 custom_weight/custom_volume 的未验证包装语义强行写入上架字段。

各字段保存独立来源和时间，完整快照时间取最早有效字段时间。新重量不会使旧属性变新；草稿只补缺项，不覆盖现有有效字段。完整混合快照使用 direct-field-dossier-v1，已接入 reviewed_snapshot，继续经过原测算和发布校验。价格、销量统计周期与跟卖许可不因读到公共页面而自动变更。

公开详情请求不启动浏览器、不携带 ERP 凭证。最多 4 次同源 HTTPS 请求处理重定向，整体限时 10 秒。访问受限退避 15 分钟，网络失败退避 5 分钟，期间直接进入草稿兜底，避免每件商品重复等待。

实测记录在 reports/direct-first-20260914；当前采样的毛子缓存未返回完整物理字段。不能以模拟测试中能跳过草稿，声称真实批次已减少草稿数量；实际收益需查看 plugin_repair_events 中的字段来源和草稿调用。

## 当前 Playwright 会话接入

用户授权复用现有浏览器后，browser_session 配置接入显式配置的现有 Playwright CLI daemon。连接使用本机既有 socket 与对应 Playwright CLI 客户端，不调用 launch/open 创建浏览器。每次只建立自己的临时商品标签页，等待商品组件加载并滚动详情，读取后关闭自己的标签页。session-detail.lock 串行化本模块访问；现有整店来源任务的浏览器及游标不变。

初始 HTTP 状态不能单独判定失败：由最终页面 JSON-LD 中唯一精确 SKU 的 Product 校验成功才接受资料。会话失效或商品身份不符退避 120 秒并保留草稿兜底；不清除登录状态，不自动启动无会话浏览器。浏览器证据保存于 data/session-detail-evidence/，权限 0600。

真实样本商品 首次导航曾报 403，但最终呈现准确商品页；再次沿用会话时初始状态为 200。准确读到标题、主图、链接。此样本尚未通过详情页取得完整包装尺寸及上架属性，不能声明完全替代草稿。
