## 模块行为

- 从候选与已通过利润核验的资料中整理标题、图片、毫米尺寸、克重量、CNY 币种；官方类目表仅在类型名称完全一致且唯一时映射类目和 type_id。保留字段来源。
- 补充资料通过 `candidate.origin.ozon_dossier` 接入，可由新商品资料模块提供。不会把供应商名称当作制造商，不编造品牌、产地、税率或字典 ID。
- `prepare` 只读核验仓库、offer 是否已存在、官方必填属性和字典值。缺项返回 `needs_input` 与 `missing`，工作流进入“需要处理”，详情展示缺项。
- `publish` 使用冻结资料和固定 offer_id 调用 `/v3/product/import`，初次创建不带库存。写请求前持久化唯一记录；保存 task_id。响应丢失后只回查，不自动重新创建。
- `reconcile` 使用 `/v1/product/import/info` 和原店 offer 查询；确认商品生成后复用官方库存写入和可售回查。库存仍来自工作流配置。
- 官方发布操作禁止 ERP 请求；后续新增的可选资料采集适配器会通过 ERP 获取原商品草稿。原 FlowB 候选适配器的人工反馈/飞书保护与全局 SKU 归属检查仍存在，因此不能宣称组合流程已彻底脱离 ERP。

## 接入方式

1. 店铺连接选择“Ozon 官方直连（无需 ERP）”，填写 Client ID、API Key、仓库 ID；不需要 ERP Token 或水印 ID。
2. 工作流的发布模块可选择“Ozon 官方直发（本地商品资料）”。未提交新任务才使用新配置，既有任务保留原计划。
3. 商品资料模块在 origin 中输出 `ozon_dossier`：

```json
{
  "source_key": "与候选一致的来源SKU",
  "name": "真实商品标题",
  "description_category_id": 30960284,
  "type_id": 97894,
  "currency_code": "CNY",
  "vat": "必须确认的账户适用税率",
  "depth": 100,
  "width": 100,
  "height": 100,
  "dimension_unit": "mm",
  "weight": 400,
  "weight_unit": "g",
  "images": ["https://实际图片地址"],
  "attributes": [],
  "provenance": {}
}
```

这只是结构示例，**不可直接上架**。每个业务字段需要非空 provenance 来源说明；attributes 必须按实际类目填写官方属性 ID、真实值和字典 ID。当前复合属性暂不支持，会明确拦截。售价来自已核验的 candidate.price，offer_id 由任务生成，资料模块不能覆盖。

只读预检接口：`POST /api/stores/{sid}/dossier-check`，JSON 为 `{source_key, price, dossier}`。使用现有登录、CSRF 和店铺所有者权限；返回 `{ready, missing, submitted:false}`，不会创建任务、上架或修改库存。
