# 查询复用与发布调度优化（2026-09-16）

## 改动

- 库存写入仅使在线列表缓存失效，保留同一执行步骤内仍在原始 TTL 内的收藏和导入记录。收藏变更、提交上架等操作仍会使相关缓存失效，并通过账户范围的 generation 通知其他执行器。
- 不增加缓存有效期，不新增跨步骤收藏缓存。库存确认仍逐次实际请求，不缓存、不合并。
- 发布通道没有可领取任务时帮助处理正常回查；除第一条专用回查通道外，其他回查通道空闲时可帮助提交。原有优先工作先执行，不增加总通道数。
- 借用通道仍通过原来的 tick 获取商品租约，遵守暂停、到期时间、店铺分配和业务校验。

## 验证

新增测试覆盖库存写入保留无关缓存、提交使其他执行器缓存失效、TTL 不延长、库存实时读取、通道借用、专用回查保留、借用时商品租约和暂停。

## 观测

以首次 stock_verified 的成功数评估最终吞吐量；记录部署时间，比较同等长度窗口。不能用审核次数或提交次数代替成功上架量，不能把刚部署当作已证实提速。

测试结果：38 项查询/调度/集群测试及 27 项发布与流水线回归测试通过，共 65 项。
部署前 30 分钟：20 件首次库存确认成功，折合 40 件/小时。原始统计保存在 output/query-scheduling-before-20260916.json。
