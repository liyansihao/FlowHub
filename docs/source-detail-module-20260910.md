# 原商品完整详情采集与本地属性映射

已接入 `ozon-direct-publisher.prepare`。未提供完整 `origin.ozon_dossier.attributes` 且店铺配置了 ERP 数据连接时，自动采集原商品详情；已提供完整资料的新模块可跳过 ERP 采集。

## 实现

- 独立 `source_detail.py` 负责资料采集和映射。专用 Node 直连通道只允许收藏查询、添加收藏、生成编辑草稿、读取草稿四种操作，不含上架、改库存或修改在线商品接口。复用本机共享限速器，固定原生 HTTP，不使用 Chrome。
- 根据来源 SKU 精确匹配收藏，生成并记录对应草稿 ID，读取俄文标题、多图、描述、类目、通用属性与变体属性。多变体未精确绑定时拒绝选择第一项。
- 通用属性与变体属性合并，同 ID 内容冲突会报告；根据官方实时类目属性定义转换为 `{id, complex_id, values}`。字典 ID 通过官方接口核验；失效 ID 仅允许根据原始文字精确匹配新 ID，不做近似品牌替换。
- 保留 SKU、草稿 ID、采集时间、字段来源，记录品牌/产地/制造商/型号需与供应商核对的字段。映射结果是原商品声明，不是供应商真实性证明。现有同款、规格冲突、人工反馈及下架保护继续生效。
- 售价、库存、仓库、税率和用于利润核验的包装尺寸不从原卖家配置覆盖。描述转入类目支持的描述属性；未知或不支持的复合属性不强行提交。
- 缓存按工作区、ERP 账号凭据指纹、SKU 隔离并加密；6 小时内复用，过期重新读已知草稿并失效旧映射。原始凭据不写入缓存。
- 收藏和草稿写入前持久记录。草稿创建响应丢失时不重复创建；已确认草稿 ID 后仅重试详情查询。初始查询失败可重试；收藏未知结果只回查。未知草稿结果需核实后恢复，不能承诺无人值守自动解决所有外部异常。
- 映射完成的资料随准备结果冻结，跨工作流阶段及进程重启可用，发布时不再次采集原商品。

| --- | ---: | ---: |
| 5023023671 | 9 | 0 |
| 1880184583 | 9 | 0 |
| 5203001553 | 16 | 0 |

第二件的旧品牌 ID 无效，已通过原品牌文本 QIACHIP 精确匹配官方字典恢复。三件当前预检仅剩本店 `vat` 配置缺失；未复制原卖家税率。创建了资料编辑草稿，**没有提交 Ozon 新商品、没有修改库存**。

明细保存在本地 `reports/source-detail-acceptance-20260910.json`，加密采集缓存位于独立验收数据库 `data/source-detail-audit/flowhub.sqlite3`。正式使用时缓存写在当前 FlowHub 数据库。

验证：当前 71 项回归测试通过，覆盖缓存复用、精确 SKU 绑定、字典 ID 恢复、多变体与属性冲突、丢响应不重建草稿、已确认草稿只读恢复，以及冻结资料跨阶段发布。修改文件 lint 与 Node 语法检查通过。

## 范围

这是对“缺少原商品资料”能力的补齐。采集数据源目前仍是 ERP，采集后的属性整理、校验、缓存与官方发布在本地完成；不等于全流程已脱离 ERP。既有正式 FlowEF 发布未被切换，旧未知提交未重发。新资料提供者可按同一 dossier 格式接入，逐步替换采集来源。
