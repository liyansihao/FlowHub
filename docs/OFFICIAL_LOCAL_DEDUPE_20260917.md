# 新发布脱离毛子导入记录查询

2026-09-17，用户授权按本地防重与 Ozon 官方发布改造。

新任务默认 official_only；原 official_preferred 不再因缺凭据、缺资料回退毛子。显式 maozi 配置仍兼容，但本次部署把现有店铺的新任务配置统一改为 official_only。已有 plugin_publications 的后端、Offer、冻结资料和 journal 不迁移。

新官方 intent 固化 source_dedupe=local_official_v1。提交前保留 SKU/store 锁、全局来源占用、来源资料/审核/飞书下架检查；新增本地跨 seller 发布记录、历史 jobs 和已知导入阳性记录检查，并实时查询 Ozon 目标 offer。任何存在或无法核实的返回均不发送 import。旧官方 intent 没有新标记时保留原毛子查询，接入现有 Windows 路由及按主机隔离的熔断。已提交或响应不明的任务只对账，不重放、不切后端。

此防重范围是本地已知来源、全局来源 claim 和目标 Offer。它不能证明其他工具/人工用不同 Offer 上架的未知商品不存在，不做全店全量扫描。

缺资料返回 awaiting_dossier，由流水线转 needs_fields，300 秒后在独立补资料通道处理。补资料除通用字段外必须通过官方资料/属性校验才可重新排队。继续使用现有指数退避、3 次失败或等待 2 小时隔离规则，不占主发布并发。资料采集阶段仍可能需要毛子；发布通道不进行现场毛子采集。等待官方补资料且没有在途命令/租约的旧 Windows 传输分配可释放。

新任务分配会跳过没有官方凭据的店铺。部署脚本 scripts/enable_official_only.py 先按账号读取 3 件 ERP 创建且 stock_verified 的历史商品，严格匹配 offer 和 CNY，仅三个税率一致时建立该账号 VAT 配置，沿用用户已有“按毛子设置”规则；不推断其他账号。--apply 保存私有配置备份，再设置 official_only，不改发布记录。所有 API 调用均使用现有限速及冷却。

验证覆盖：零 ERP 调用直发；历史阳性/另一 seller/已存在官方 Offer 拦截；异常响应不当作不存在；缺资料进入独立队列且不回退；旧任务保留原后端及查询；提交/库存响应丢失后的恢复不重复写；补资料必须通过官方校验；缺凭据店铺跳过；VAT 三样本身份、货币及一致性。

运行限制：接入官方 API 不意味着原商品属性已经齐全。部署前快照 139 条未建发布记录任务中，130 条官方资料不完整、9 条所在店铺无官方凭据；只有 2 条有可复用的完整来源草稿缓存。不能把解除查询依赖等同于上架吞吐已提高。
