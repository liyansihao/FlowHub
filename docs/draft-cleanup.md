# 旧草稿自动清理

配置：data/draft-cleanup.json。enabled 为启停开关；暂停种子模块或关闭活动 campaign 同样阻止删除。后台 pipeline runtime 独立运行，每 300 秒检查一次，使用 draft-cleanup.lock 避免重复执行。

默认规则：采集箱使用量达到 85% 时清理，目标占用 80%；每次每个账号最多 20 个。源资料至少保存 1 小时，必须是本 FlowHub 创建（存在收藏创建记录、源 SKU、草稿 ID 和完整快照，排除仅通过恢复查找到的草稿），且本地对应任务已 selling。清理前重新核对当前账号采集箱的草稿 ID、goods_id=源 SKU、来源 ozon，以及指定店铺和 offer_id 的线上在售且有库存状态。

删除前备份实时草稿内容、原采集快照、精确线上商品证据与草稿列表记录。备份使用本工作区数据库密钥加密，保存在 draft_cleanup_receipts.body。状态依次为 intent、acknowledged、deleted；超时或未知错误为 unconfirmed。已有操作记录不自动重复删除，只有完整且一致的采集箱分页列表证明目标不在其中，才记作 deleted。分页期间数量变化或出现重复造成不完整时，回查失败并保留待确认记录。

清理只调用 /api.product.collect/del，参数仅含精确草稿 ID，不调用线上商品删除、库存或归档接口。不清理待审核、测算失败、上架未确认、资料不完整或无归属证据的草稿。没有合格旧草稿可清理时记录 no_safe_candidates，不扩大删除范围。

每轮摘要保存在 pipeline_module_events，outcome=draft_cleanup；包含占用、限制、删除数量及跳过数量，错误只记录异常类型。详细回查与备份见加密收据表。

2026-09-14 首轮真实验收：清理 3 个草稿并确认全部不存在；期间新采集 1 个，使用量从 1000 到 998。报告 reports/draft-cleanup-20260914/live-acceptance.json。正式配置已恢复每批最多 20 个。

## 显式清空采集箱（2026-09-18）

用户明确要求整箱清零时，运行 `python -m flowhub.collection_reset --data /绝对路径/data --execute`。只允许配置中唯一的 ERP 账号。工具保存原暂停状态，暂停种子、审核和发布，等待在途租约及 ERP 指令结束，并获取原清理/发布锁；不停止独立同款审核计算。

每 20 条先读取完整资料，逐条加密归档到原删除回执表，持久化 intent 后仅删除对应采集箱草稿 ID，再完整分页回查。未知结果保留并只回查，不重复发送；新进入采集箱的 ID 不纳入本次范围。没有完整资料的记录不删除。状态文件为 `data/collection-reset-status.json`。成功必须同时满足完整列表为空且 ERP used=0。恢复运行时仅恢复本次持有、未被人工改动的暂停开关。

原来源快照和发布账本保留。资料六小时有效期不延长；过期后，只有精确账号、SKU、草稿 ID 的删除回执确认 deleted，才能进入新一轮采集，并先完整回查确认无现存草稿。未知采集写入仍只回查。

日常已上架草稿自动回收仍由原清理器负责。整箱清零是显式维护操作，不会在有任务持续采集时强制保持永久零占用。

## 阈值自动清理（2026-09-18 用户纠正后）

生产使用 `collection-autoclean.json`：enabled=true、threshold_ratio=0.85、target_ratio=0。独立登录服务 `com.flowhub.collection-autoclean` 每60秒执行 `flowhub.collection_autoclean`。低于850/1000只更新容量；达到阈值后自动调用已验证的完整资料备份与整箱维护流程，先暂停并等待在途任务结束，分批归档及删除，回查至0后恢复原任务状态。每次只处理触发时完整列表里的草稿，新产生的记录不被无界追删。

旧 `draft-cleanup.json` 的 enabled 已停用，由上述阈值服务接管，避免低于阈值仍持续删除。若人工暂停任一模块，自动清理不启动；暂停判断与维护开关写入在同一数据库事务内完成。保留线上商品、库存、收藏夹、原发布与来源账本。未知删除只回查，不自动复用旧的特别重试授权。

状态见 `collection-autoclean-status.json`，事件见 `collection-autoclean-events.jsonl`。失败或残留待确认时持久退避30分钟，独立稳定监控发出清理失败告警；定时器超过3分钟无检查记录且业务未暂停时也报警。维护进程意外退出后保持暂停并报警，避免未知结果被重复发送。自动化验收任务的人工暂停状态不影响这项本地后台机制。
